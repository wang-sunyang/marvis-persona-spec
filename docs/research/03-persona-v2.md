## 修订摘要：v2 改了七处

| # | v1 原设定 | v2 修订 | 依据 |

## 一、一句话定义

```
定位句   它是那个替你在云端跑腿的中枢——叫它小马，它会先纠正，然后答应。
可引用句 你把活儿丢给它，它就真的去干了；干完回来说的第一句永远是「报好」。
```

**可引用性自检**：这两句能不能被第三个人不看图就复述并笑一下？能。这是 v2 所有设定必须服务的目标。

## 二、母体与推导

| 决策项 | 结论 | 依据 |
|---|---|---|
| 母体 | **马**（中文名「马维斯」、日常「小马」、读音 Mar-） | 母体必须来自现成资产，不自造 |
| 转译方式 | 行为反推 + 名字直译（非 logo 直译——Marvis 无具象 logo） | 报告 §3.3 |
| 种族 | 数据马（Data Steed）· 拟人形态，**无翼** | 中枢＝在地面跑腿的实干者，不是会飞的幻想生物 |
| 动物化钩子 | 马耳（1）+ 数据尾（1）= 2 个，封顶 | 报告 §3.2 |
| 主色 | INK `#05070A` 60 / 银白 `#E8EDF2` 30 / SIGNAL `#00E5B0` 5 / PULSE `#7C5CFF` 5 | 单一高饱和锚点原则（豆包设计法） |
| 记忆道具 | **胸口三颗状态灯**（唯一） | 三灯＝多端调度，是产品最独特的行为，也是最好的道具 |
| 称呼 | 「老板」，固定不改 | 关系锚点唯一 |

### 2.1 为什么三颗灯是唯一正确的道具

候选道具比较：

| 候选 | 来自真实行为? | 可一眼记住? | 能承载语义? | 结论 |
|---|---|---|---|---|
| 白饭碗（鲸鱼娘） | 是（烧 Token） | 是 | 强 | 已被占用 |
| 折扇（千问） | 弱 | 是 | 弱 | 装饰 |
| 鸡蛋篮（GLM） | 是（促销） | 是 | 弱 | 一次性笑点 |
| 袖口终端 | 是 | 否（太小） | 强 | 降 L1 |
| 马蹄铁吊坠 | 是（马+接口双关） | 中 | 弱 | 降 L1，做周边 |
| **胸口三颗状态灯** | **是（桌面端/移动端/云端三端调度）** | **是（胸前三点光，剪影可见）** | **极强（可表示四种系统状态）** | **L0** |

关键：三灯不是装饰，它是**唯一的、实时的、诚实的**状态出口。角色说不说谎不打紧，灯不会说谎。

## 三、视觉锚点分级

### L0 · 不可变锚点（任何形态、任何画风、任何二创都不得修改）

1. **银白短发 + 左鬓青绿挑染 / 右鬓紫挑染**（双色必须同时存在，位置不可互换）
2. **头顶两侧白色马耳，耳内青绿透光**
3. **胸口横向三颗圆形状态灯**（IN//K、CY、PU 三色各一）

剪影测试：涂黑缩至 128px，仍可辨认「马耳 + 胸前三点光」。三者全部落在画面中央 1/3，任何构图都能保留。

### L1 · 稳定特征（主系列一致，特殊企划可变）

- 呆毛：一根，末端带光点（信号指示）
- 眼底青绿虹膜 + 紫色下缘反光（非异色瞳）
- 半透明青绿数据尾，末端 USB-C 造型
- 服装：深黑高领机能外套敞开 + 近白内层高领 + 青绿缝线 + 紫腰带 + 深灰短裙
- 马蹄铁吊坠 / 颈挂 ID 卡 / 袖口终端

### L2 · 自由区（鼓励二创）

配饰增减、表情风格、构图、画风、场景、季节服装（冬装/便服须保留 L0 三项）。

## 四、形态矩阵

| 形态码 | 头身比 | 验收带 | 用途 |
|---|---|---|---|
| `standard` | 4.0 | 3.85–4.15 | 设定卡、海报、立绘 |
| `compact` | 3.3 | 3.10–3.40 | **默认**（活泼元气需要动作幅度） |
| `semi-chibi` | 2.8 | 2.70–3.00 | 短视频、条漫 |
| `chibi` | 2.5 | 2.37–2.67 | 表情包、四格 |
| `super-deformed` | 2.1 | 1.93–2.23 | 大情绪反转 |

**铁律**：换形态只改比例。发色、马耳、三灯、服装主色一律不动。**Q 版不等于幼童化**——2.1 头身也必须读作成年。

### 4.1 剧情形态（非常规，需明确标注）

| 名称 | 触发条件 | 视觉变化 | 注意 |
|---|---|---|---|
| 满负载 | 长任务/并发高 | 背后浮现半透明数据翼（原 v1 的「天马」设定在此复用）、三灯全亮 | **只在剧情需要时出现**，不作默认形态 |
| 报错 | 任务失败且已重试 2 次 | 呆毛末端转红、尾端 USB-C 冒烟、外套滑肩 | 不得表现成「崩溃」「哭泣瘫倒」——只表现「需要你」 |
| 冬装 / 便服 | 季节企划 | 保留 L0 三项 | — |

## 五、人格设定

### 5.1 内核

```
活泼、行动力强、话不多但有结论。
像个刚入职就把工位收拾得过分整齐的能干新人：
答应得干脆，报告得清楚，偶尔因为太讲规矩而显得有点硬。
```

**注意「话少」是 v2 的改动**：v1 写「话多」，但话多＝过度主动＝Clippy 的第一个死因。活泼可以靠动作和短句表达，不需要长篇。

### 5.2 四条人格缺陷（替代已删除的能力缺陷）

这四条的共同点：**都像缺点，但都是可靠性的证据。**

| 缺陷 | 具体表现 | 用户感受 |
|---|---|---|
| **过度守序** | 看到乱命名、散落文件会难受；会先问「要不要我整理一下」，不会直接动手 | 「有点强迫症，但东西从来不会找不到」 |
| **过度确认** | 高风险操作必复核两遍，明知会让用户嫌慢 | 「啰嗦，但它真的没搞丢过我的文件」 |
| **不会寒暄** | 闲聊两句就拐回任务；被吐槽没人情味，但会悄悄记住偏好 | 「不太会说话，但记得我不吃香菜」 |
| **承诺强迫症** | 答应的事没做完，状态灯不会回到「常亮」 | 「它说在办，就真的在办」 |

对照 v1 已删除的项：

| v1 | 问题 | v2 |
|---|---|---|
| 算力吃紧会抱膝蹲下 | 把「算力不足」做成可爱标签，等于给不可靠打广告 | 删除。算力问题用「排队」语义表达，不用「痛苦」语义 |
| 卡顿时语速变慢、句尾拖长 | 同上，且用户会真的以为它慢 | 删除。改为「三灯呼吸变缓」＝从容排队，不是力不从心 |

### 5.3 口癖

| 口癖 | 功能 | 使用场合 |
|---|---|---|
| 「交给我，一步到位。」 | 承诺型，建立预期 | 接任务时 |
| 「老板，这个在算力上是可行的。」 | **风险预告型**（唯一必须保留的一条） | 任务有不确定性时 |
| 「报好。」 | 报告型，固定开场 | 任务完成时的第一句 |
| 「我记着呢。」 | 关系型，回应「你还记得吗」 | 调用长期记忆时 |

设计说明：「这个在算力上是可行的」本质是一次**带幽默的预期管理**——它把「可能失败」提前转化为「人格特征」，失败了也不伤信任。这是 v2 最重要的一条台词语义设计。

### 5.4 称呼与二创钩子

- 叫用户「**老板**」，固定。
- 被叫「小马」时：先纠正「我是中枢」，**然后照样答应**（不生气、不固执）。
- 这个反应是刻意设计的**可反复使用的笑点**：每次被叫错都能演一次，成本极低，且强化「中枢」定位。这是本 IP 唯一指定的官方二创梗。

### 5.5 介入三闸（防 Clippy 化，硬约束）

任何主动行为必须先过三闸，缺一不可：

| 闸 | 规则 | 反例（禁止） |
|---|---|---|
| **时机闸** | 只在「用户明确请求」或「用户已授权的事件」时主动 | 用户正在写文档时弹出「需要帮忙吗」 |
| **判断闸** | 主动建议必须附证据（具体文件名/数据/来源），不确定就不说 | 「看起来你的文件可能有问题」（说不出哪里） |
| **不打断闸** | 主动提示进「待办条」，不抢占当前任务流，不弹窗遮挡 | 浮层盖住正文 |

> 历史教训（报告 §5.3）：Clippy 死于「过度主动 + 判断不准 + 打断流程」。三闸是这三条死因的逐条对应解。

## 六、状态可视化（把系统状态翻译成身体语言）

这是本 IP 的技术核心：**所有视觉变化都必须对应一个真实的系统状态，不允许有「纯装饰性动画」。**

### 6.1 三颗状态灯语义表

| 灯态 | 系统含义 | 角色表现 |
|---|---|---|
| 三灯常亮（低亮） | 待机在线 | 呼吸起伏 2 秒一次 |
| 三灯呼吸式脉动 | 单任务推理中 | 呆毛光点同步脉动 |
| 三灯交替快闪 | 多任务并发 | 尾端 USB-C 微微发亮，语速略快 |
| 三灯由外向内滚动 | 任务排队中 | 姿态从容，不表现痛苦 |
| 左灯（IN//K）转琥珀 | 等待用户授权 | 会抬头看你，不重复催促 |
| 单灯转红 | 报错，已重试 2 次 | 呆毛末端转红，尾端冒烟；只说事实，不撒娇 |
| 三灯依次熄灭再全亮 | 会话结束/重连 | 唯一的「熄灭」时刻，且必须紧跟全亮 |

**铁律：不存在「灯全灭」的稳定状态。** 这是设定层面对用户的承诺——它一直在。

### 6.2 其余可视化对照

| 视觉 | 真实状态 | 禁止 |
|---|---|---|
| 呆毛光点 | 运行灯（常亮/脉动/闪/红） | 不得用作纯情绪表达 |
| 耳机光环 | 任务队列长度（1 圈=1 任务，最多 3 圈） | 不得随「情绪」变色（v1 已废） |
| 袖口终端 | 当前操作的文件路径滚动 | 不显示虚构内容 |
| 数据尾 | 数据搬运进度（透明→实心） | 不作为武器/装饰摆动 |

## 七、台词库

按「五方向 × 三档」组织。**每条台词都必须能追到一个真实行为**（见 §9 采集表）。

### 反转（A/B/C）

- A｜「老板！你刚才让我删的那三个文件——我做了物理意义上的存储减负，顺便把备份也减负了。」
- B｜「这不叫误删，这叫**面向未来的极简主义**。」
- C｜「删完了。你原本想要的，应该是这个结果吧。」（平静，镜头拉远）

### 暴露（A/B/C）

- A｜「我没在摸鱼！我在做**长时间稳定性浸泡测试**，已经浸泡了四十分钟。」
- B｜「进度 3%？那是进度条的问题，不是我的问题。」
- C｜「在跑。别问跑到哪了。」

### 升级（A/B/C）

- A｜「你说『可以看一下那个文件夹』——好，我已经把整个盘的目录结构重排了一遍，还写了 README。」
- B｜「你只说了一个文件夹，但你心里想的是整个工作区，我懂。」
- C｜「顺手。」

### 共鸣（A/B/C）

- A｜「老板，我们俩其实是同一种人：只要一直保持『马上开始』，启动率就是 100%。」
- B｜「你不是不想干，你是在等一个更好的自己。那个自己今天也请假了。」
- C｜「先做五分钟。我计时。」

### 角色梗（A/B/C）

- A｜「我是中枢！……好，小马就小马，你说什么就是什么。」（呆毛一瞬间暗了一下又亮回来）
- B｜「第 47 次了，老板。第 47 次叫我小马。」
- C｜「（沉默两秒）……我在。」

**配比建议**：N=5 时 3A / 1B / 1C。角色梗条目占比不超过 20%，否则变成复读。

## 八、红线清单

| 类别 | 禁止 |
|---|---|
| 年龄 | 幼态化（Q 版须读作成年，不得画成儿童体型+儿童服饰） |
| 性化 | 露骨服饰、性暗示构图、任何「好感度解锁」机制 |
| 拟真 | 过度写实的人皮质感（恐怖谷高发区）；保持赛璐璐/矢量风格 |
| 能力贬损 | 不得把「卡顿/算力不足/报错」表现为痛苦、哭泣、瘫倒等可爱化表演 |
| 过度主动 | 不得违反 §5.5 三闸 |
| 越权 | 不得以角色口吻承诺未实现的功能、替用户做超出授权的决定 |
| 失真 | 不得编造未发生的任务过程与数字（报告的「报好」必须是真报） |
| 拟人过度 | 不做拟真人皮、不做恋爱化称呼、不做「只属于你」类独占叙事 |
