
# 角色一致性工程手册 · 可执行套件 v1

> 用途：把一个「设定好的角色」变成「每次出图、每条视频都长一样的角色」。
> 适用：原创 IP / 品牌拟人形象 / 短视频虚拟角色 / 开源项目吉祥物。
> 说明：本手册是方法论与模板，不含任何第三方 IP 的具体资产，可自由改写自用。

---

## 使用说明

本手册分十节，对应角色从定义到交付的完整链路。**每节末尾带「可复制段落」**，直接粘进你的项目仓库即可使用。

最短路径（只有 1 天时间）：

1. 填 §1 角色定义卡（30 分钟）
2. 定 §2 锚点分级（关键，决定后面所有一致性）（30 分钟）
3. 定 §3 形态矩阵中的默认档（15 分钟）
4. 抄 §9 许可声明（15 分钟）
5. 其余按需

## §1 角色定义卡（模板）

一张卡必须能在 60 秒内让外人说清「这是谁、像什么、为什么长这样」。

```yaml
身份:
  名字: ""
  编号: ""            # 用于资产管理，如 MV-01
  种族/类别: ""        # 拟人形态的物种来源
  一句话定位: ""       # ≤20 字，说清「它替你做什么」
  可引用句: ""         # ≤30 字，能被别人转述的那句话（最重要）

母体:
  品牌资产: ""         # logo / 名字 / 产品行为，必须三选一有出处
  转译方式: ""         # logo直译 / 印象抽象 / 行为反推
  为什么是它: ""       # 一句话，能说服人

外观:
  年龄感: ""           # 必须明确成年
  身高: ""
  发: ""               # 颜色 + 长度 + 挑染位置与色
  动物化钩子: []       # 最多 2 个
  眼: ""
  服装主色: ""
  记忆道具: ""         # 1 件，必须来自真实行为
  二级配饰: []

性格:
  内核: ""
  行为出处: []         # 每条性格必须对应一条可观察的真实行为
  口癖: []             # 2-3 条，至少 1 条承担功能（承诺/预期管理）
  称呼用户: ""
  被误称时的反应: ""   # 高质量二创钩子

边界:
  不做: []             # 禁用清单，见 §8
```

## §2 视觉锚点分级（一致性的核心机制）

**原理**：一致性不是「所有元素都不许变」，而是「少数元素绝对不变，其余自由」。不分级的结果是——要么僵硬到无法创作，要么松散到认不出。

| 级别 | 名称 | 规则 | 建议数量 |
|---|---|---|---|
| **L0** | 不可变锚点 | 任何形态、任何画风、任何二创都不得修改 | 恰好 3 个 |
| **L1** | 稳定特征 | 主系列必须一致，特殊企划可变 | 3-5 个 |
| **L2** | 自由区 | 鼓励二创作者自由发挥 | 不限 |

**L0 选取标准（三条同时满足）**：

1. 能在剪影测试中保留（涂黑后仍可辨认）；
2. 与其他同类角色不重合；
3. 不依赖特定画风（Q 版也能画出来）。

**剪影测试方法**：把立绘填成纯黑，缩到 128px，让 5 个没看过设定的人描述「这是什么角色」。描述里出现频次最高的特征，就是真正的 L0。

> 常见错误：把配饰当 L0（耳环、吊坠、ID 卡）。配饰在不同画风里最容易丢，放 L1。

**可复制段落**：

```
【L0 锚点】1. ______　2. ______　3. ______
（任何情况下不得修改；二创规范中须明确列出）

【L1 特征】发色值 / 服装主色 / 记忆道具 / 动物化钩子位置
（主系列一致；特殊企划需在说明中标注）

【L2 自由区】配饰增减、表情风格、构图、画风、场景
（鼓励二创发挥，不设限）
```

## §3 形态矩阵（头身比量化）

**为什么必须量化**：不量化时，「画个 Q 版」会顺手改衣服、改发色、改年龄，观众认不出是同一个人。量化后，「Q 版」只是比例变化，身份不变。

| 形态码 | 目标头身比 | 严格验收带 | 适用场景 |
|---|---|---|---|
| `standard` | 4.0 | 3.85 ~ 4.15 | 站姿、概念立绘、大幅海报 |
| `compact` | 3.3 | 3.10 ~ 3.40 | 动感动作、坐姿、中景 |
| `semi-chibi` | 2.8 | 2.70 ~ 3.00 | **默认基准**，通用 |
| `chibi` | 2.5 | 2.37 ~ 2.67 | 四格漫画、表情包 |
| `super-deformed` | 2.1 | 1.93 ~ 2.23 | 大情绪反转、贴纸 |

**铁律**：形态只控制身体比例与头身结构。**绝不改变**年龄、身份、服装细节、发色、生理特征。

**测量方法**（无需专业工具）：

1. 取头顶（不含呆毛）到脚底的总高度 H；
2. 取头顶到下巴的高度 h（含头发厚度，与总高同口径）；
3. 头身比 = H / h；
4. 误差超过 ±0.15 即视为不合格，返工。

**脚本化**：可用 OpenCV 或 PIL 做半自动测量——先人工标注头顶/下巴/脚底三点，脚本算比值并输出叠图。比纯人工快 5 倍，且每次口径一致。

## §4 表情与肢体库

### 4.1 表情分级

| 级别 | 数量 | 用途 | 复用率 |
|---|---|---|---|
| 基础 | 6 | 平静 / 笑 / 惊讶 / 为难 / 认真 / 生气 | 90% |
| 情境 | 12 | 得意 / 委屈 / 无语 / 兴奋 / 疲惫 / 心虚 / 思考 / 疑惑 / 尬笑 / 认命 / 挑衅 / 放空 | 8% |
| 极端 | 6 | 颜艺级，仅用于爆点 | 2% |

**关键约束**：极端表情不得改变 L0 锚点。颜艺的方向是「五官变形」，不是「换个人」。

### 4.2 肢体最小集

虚拟角色做视频时不需要全身动作，只需要：

- 呼吸（2 秒循环，幅度 1-2px）
- 眨眼（随机 3-6 秒一次，闭眼 0.1 秒）
- 口型（说话时 2-3 帧交替）
- 点头 / 摇头
- 抬手（指向卡片、比 V、扶额）
- 抖一下（受惊）

这 6 个动作 + 24 个表情，足以支撑日更。

## §5 事实锚点库（Fact Anchor）

**定义**：一条来自真实使用过程的、可复核的具体事件。它是性格的唯一合法来源。

**为什么重要**：凭空设定的性格没有二创生命力，因为二创作者无法验证，也就无法在此基础上加戏。有出处的性格，二创作者会自己往上垒。

### 5.1 采集表模板

| ID | 真实行为 | 可观察证据 | 用户感受 | 可加工方向 | 已用? |
|---|---|---|---|---|---|
| FA-001 |  | 日志 / 截图 / 记录 |  | 反转/暴露/升级/共鸣/角色梗 |  |
| FA-002 |  |  |  |  |  |

**采集原则**：

1. 只记**发生过的**，不记「我们设计成会这样」；
2. 必须有证据（日志、截图、录屏、可复现步骤）；
3. 优先采集「用户会吐槽的」——吐槽点是笑点密度最高的地方；
4. 每条至少保留 3 个月，因为人设需要时间沉淀。

### 5.2 采集清单（通用提示）

对着自己产品问这些问题，答案就是锚点：

- 它在什么情况下会「装死」？
- 它最容易在哪个环节出错，出错后怎么解释？
- 它有什么多余但改不掉的小动作？
- 用户最常误解它哪一点？
- 它有没有「明明能做却说不能」的时刻？
- 它有没有「明明不该做却做了」的时刻？
- 它和同类产品比，最明显的怪癖是什么？

## §6 喜剧加工流水线

拿到锚点后，按「方向 × 档位」加工。**方向和档位是两个独立变量**，不要混。

### 6.1 五个方向

| 方向 | 机制 | 加工公式 | 例子（虚构） |
|---|---|---|---|
| **反转** | 结果与预期对调 | A 被重新定义为 B | 误删文件 →「物理意义上的存储减负」 |
| **暴露** | 把私下的偷懒摊上台面 | 承认 + 合理化 | 长时间摸鱼 →「系统浸泡压测」 |
| **升级** | 顺杆爬，把许可做大 | 用户给一寸，它要一尺 | 「可以吃冰箱里的」→「整台冰箱是我的便当盒」 |
| **共鸣** | 说出用户自己的心声 | 用一个所有人都有的经验 | 「只要一直『马上开始』，成功率就是 100%」 |
| **角色梗** | 复用已有标签 | 把标签再强化一次 | 反复讨要资源、反复提到同一个道具 |

**优先原则**：比较时优先保留原素材本来的好笑方式，不要一律改成反转。全部反转会让角色变成单一维度的杠精。

### 6.2 三个档位

| 档 | 名称 | 表现手法 | 适用 |
|---|---|---|---|
| A | 日漫冲击 | 详实场景、集中线、颜艺、拟声字 | 开篇钩子、爆点 |
| B | 漫画式爆发 | 拍桌指控、事态失控、夸张动作 | 中段升级 |
| C | 克制冷幽默 | 靠台词、眼神、留白 | 结尾收束、高级笑点 |

**配比**：N=5 时 3A / 1B / 1C；其他数量按 60% / 20% / 20% 靠。刻意压低某一维度可以制造反差（例如整条只有 1 个 A，其余全 C，会显得特别冷）。

**标注方式**：档位标在「落点格」（笑点爆出的那一格），不是开头。

## §7 出片规范（短视频向）

### 7.1 硬参数

| 项 | 建议值 | 理由 |
|---|---|---|
| 时长 | 60-90 秒 | 完播率与信息量平衡 |
| 画幅 | 横屏 16:9（可另出竖屏 9:16） | 竖屏需重排版式，不是裁剪 |
| 配音 | 无 | 打字音比人声更「AI」；也省掉配音一致性成本 |
| 音效 | 代码按时间轴合成 | 零版权风险，且不会错位 |
| 单集文件 | 一个结构化文件 | 台词、说话人、表情、卡片触发词全在里面 |
| 改一句重出 | < 2 分钟 | 这是能日更的前提 |

### 7.2 分集文件字段

```
scene: 场景编号
speaker: 角色ID
emotion: 表情ID
line: 台词原文
card: { at_word: 触发词, type: 卡片类型, content: 内容 }
sfx: 音效ID
duration_hint: 秒（可按字数自动算）
```

### 7.3 节奏规则

- 每句停留时间按字数算，不按感觉；
- **一条视频里同时出现「要读卡片」+「要读台词」时，停留时间必须加倍**，否则观众来不及看；
- 打字音避开高频区（尖锐方波 + 高音区配乐，十几秒就烦）。整体配乐降一个八度更耐听。

### 7.4 封面规范

固定版式：角标（DAY N）+ 两行主字（含一个高亮词）+ 角色固定站位。
**只换字、换人，不改版式**——版式一致才形成「系列感」，系列感是回访率的来源。

## §8 禁用清单（红线）

任何情况下不得出现：

| 类别 | 具体禁止 |
|---|---|
| 年龄 | 幼态化主角（Q 版不等于幼童化，2.1 头身也必须读作成年） |
| 性化 | 露骨服饰、性暗示构图、「好感度解锁内容」机制 |
| 拟真 | 过度写实的人皮质感（恐怖谷高发区） |
| 越权 | 角色代表产品对外发言时，超出授权范围（承诺功能、替用户决策） |
| 失真 | 编造未发生的过程与数字 |
| 混淆 | 未标注「非官方」的社区作品不得使用品牌官方视觉标识 |

## §10 上线前总检表

### 身份一致性
- [ ] L0 锚点恰好 3 个，且通过剪影测试
- [ ] 所有形态下 L0 与发色、服装主色未变
- [ ] 头身比落在目标档验收带内（±0.15）
- [ ] 记忆道具存在且形态正确

### 内容真实性
- [ ] 片中每条「事实性陈述」都能追到证据
- [ ] 数字全部来自系统记录，无手填
- [ ] 没有模型补写的「人类说过的话」

### 合规
- [ ] 无幼态化、无性化、无拟真人皮
- [ ] 许可声明已发布，分层清晰
- [ ] 社区作品已标注「非官方」
- [ ] 涉及自动化行为的部分有频率限制与人工可撤回机制

### 传播
- [ ] 有一句 ≤30 字、可被转述的话
- [ ] 有 1 件来自真实行为的记忆道具
- [ ] 有 1 个可被反复使用的二创钩子（例如「被叫错名字时的反应」）
